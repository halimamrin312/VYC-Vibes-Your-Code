# Project Development Schedule: M&A Due Diligence Swarm

This document outlines the collaborative, 9-day implementation plan (June 23 – July 1) for a team of **4 developers** to build and integrate the Automated M&A Due Diligence Swarm.

---

## 👥 Team Domain Assignments

To minimize merge conflicts and ensure parallel progress, each developer is assigned a clear ownership domain:

*   **Developer A: Lead Architect & Agent Engineer (ADK & Orchestration)**
    *   *Domain:* Core ADK framework setup, central Orchestrator loop, dynamic agent registry, state management, and Human-in-the-Loop (HITL) checkpoints.
*   **Developer B: Backend & Integrations Engineer (API, Database & MCP)**
    *   *Domain:* FastAPI server setup, endpoints for ingestion & streaming chat, local vector storage configuration, and custom MCP server wiring.
*   **Developer C: Frontend Developer (React/Vite Web App & Mobile UI)**
    *   *Domain:* Mobile-responsive UI dashboard, drag-and-drop document upload interface, chat components, and memo visualization.
    *   *Guidelines:* Sleek dark-mode aesthetic with custom animations.
*   **Developer D: Sub-Agent & Prompt Specialist (Domain Logic & RAG)**
    *   *Domain:* Writing specialized sub-agent prompts and tools (Financial, Legal, Ops, Sentiment), building mock target data ("Acme Corp"), and writing RAG loaders.

---

## 📅 Daily Milestones (June 23 – July 1)

### Phase 1: Foundation (June 23 – June 24)
> [!NOTE]
> Focus is on setting up the project skeleton, establishing API communication contracts, and compiling test data.

#### **Day 1 (June 23): Environment Setup & Architecture Skeleton**
*   **Developer A:** Initialize the Git repository. Set up the Python project skeleton (using ADK) and implement the dynamic agent loader framework in `swarm/orchestrator.py`.
*   **Developer B:** Bootstrap the FastAPI server in `backend/`. Define the API schemas and JSON contracts for communication between the UI and the agent.
*   **Developer C:** Scaffold the frontend application using Vite (React). Establish the global theme, vanilla CSS variables (dark-slate tech theme), and basic page routing.
*   **Developer D:** Gather and create mock data for "Acme Corp" (a folder containing a financial CSV, a legal contract PDF with a planted liability clause, and operational logs). Save this under `data_room/mock_data/`.

#### **Day 2 (June 24): Ingestion Pipeline & Basic Chat Connection**
*   **Developer A:** Implement the first version of the Orchestrator routing loop, reading configuration from `.env` and loading empty sub-agents.
*   **Developer B:** Create the file ingestion API endpoint (`/api/ingest`). Write the local parser script to read uploaded CSVs and save them in the data room.
*   **Developer C:** Build the mobile-responsive chat container and the document uploader component in React. Connect it to the backend `/api/ingest` endpoint.
*   **Developer D:** Write the initial system prompt templates in `swarm/prompt_templates/` for the Orchestrator, Financial Auditor, and Legal Compliance agents.

---

### Phase 2: Core Agent & Feature Development (June 25 – June 27)
> [!TIP]
> The primary logic of the Financial and Legal agents is built and wired to the UI.

#### **Day 3 (June 25): Financial Auditor Agent & Local Data Parsing**
*   **Developer A:** Integrate basic tool call routing into the ADK Orchestrator so sub-agents can invoke python scripts or vector search.
*   **Developer B:** Set up the local vector database (e.g., SQLite or FAISS) for storing parsed PDFs, configuring the embedding generation logic.
*   **Developer C:** Implement dynamic upload feedback and status indicators (e.g., "Ingested financial statements", "Processing legal PDF").
*   **Developer D:** Complete the `financial_auditor.py` agent. Implement the `pandas_analyst.py` tool to parse the mock CSV and calculate burn rates, churn, and debt ratios.

#### **Day 4 (June 26): Legal Compliance Agent & Local RAG**
*   **Developer A:** Implement memory storage so agents can reference historical context from the uploaded documents across chat turns.
*   **Developer B:** Build a local RAG extraction tool that segments PDFs and does similarity search without leaking data to external indices.
*   **Developer C:** Design the Markdown Viewer component to display the formatted investment memo generated by the Orchestrator.
*   **Developer D:** Complete the `legal_compliance.py` agent. Wire it to the local RAG tool to search target contracts for liability clauses and "poison pills".

#### **Day 5 (June 27): Operations & Brand Sentiment Agents**
*   **Developer A:** Standardize error-handling and API responses across all sub-agents to prevent a crash in one agent from halting the swarm.
*   **Developer B:** Write the API endpoint for streaming chat messages from the Orchestrator to the UI.
*   **Developer C:** Wire the frontend chat window to the backend streaming endpoint, ensuring messages render smoothly.
*   **Developer D:** Build the `ops_evaluator.py` and `brand_sentiment.py` agents. Code a web-search tool to fetch sentiment indicators without sharing confidential company metadata.

---

### Phase 3: Advanced Integrations & HITL Checkpoints (June 28 – June 29)
> [!IMPORTANT]
> Establish the Human-in-the-Loop workflow and configure custom MCP servers.

#### **Day 6 (June 28): Human-in-the-Loop (HITL) Implementation**
*   **Developer A:** Implement ADK's pause/resume state management in the Orchestrator. Create the logic to trigger a "Red Flag" pause when the Legal agent flags a high-priority risk.
*   **Developer B:** Expose backend endpoints `/api/hitl/pause` and `/api/hitl/respond` to manage the interactive verification loop.
*   **Developer C:** Add interactive HITL prompts to the chat UI (e.g., action buttons: "Proceed with Deducted Valuation", "Halt Due Diligence", "Ignore Risk").
*   **Developer D:** Write test cases triggering the HITL loop. Tune agent system prompts to ensure they properly identify when to halt and ask the user for guidance.

#### **Day 7 (June 29): MCP Server Integrations**
*   **Developer A & B (Pair):** Build and configure the file-system and public MCP servers (SEC EDGAR and CourtListener MCPs). Wire them as tools for the Financial and Legal agents.
*   **Developer C:** Enhance UI responsiveness. Integrate subtle micro-animations (loading spinners, agent typing indicators, panel transitions).
*   **Developer D:** Optimize prompt templates to incorporate external search results retrieved from the MCP servers.

---

### Phase 4: Verification, Security & Polish (June 30 – July 1)
> [!CAUTION]
> Focus is on verifying security protocols (zero-leakage), performance testing, and setting up remote tunnels for phone access.

#### **Day 8 (June 30): Remote Tunneling & Security Verification**
*   **Developer A:** Run security audits. Ensure outgoing API search queries are properly sanitized by `data_sanitizer.py`.
*   **Developer B:** Expose the local FastAPI server using a secure tunnel (Tailscale or Ngrok). Verify that you can access the API endpoint securely.
*   **Developer C:** Test the React UI on mobile viewports. Connect your phone to the server via the secure tunnel and test file uploads.
*   **Developer D:** Run E2E evaluation. Seed different M&A scenarios (e.g., retail, manufacturing) to verify that the Orchestrator dynamically adjusts analysis.

#### **Day 9 (July 1): Final Polish & Code Freeze**
*   **Team (All):** Conduct a complete end-to-end dry run. Verify all agent paths function correctly, CSV data is calculated accurately, and the investment memo compiles properly.
*   **Deliverable:** Freeze the code and package the application (`docker-compose.yml` or standard start scripts). Prepare the repository's `README.md` and initial outline for the Kaggle Writeup.
